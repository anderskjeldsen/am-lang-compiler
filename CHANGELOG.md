# AmLang Compiler Changelog

All notable compiler changes are documented here.

## [0.16.0] - 2026-11-22

Changes since v0.15.0.

### Added

- **Integer division by zero throws `ArithmeticException` in a checked build, the default for `amlc test`** (2026-11-22, Redmine #427). `a / b` and `a % b` with an integer `b == 0` rendered plain C division, so the program died with SIGFPE on x86 (a Guru on 68k AmigaOS) or carried on with an unspecified value (0 on ARM64, garbage on PowerPC). Now, in a checked build, integer `/`, `%`, `/=` and `%=` (Byte to ULong, signed and unsigned) check the divisor first: 0 throws `Am.Lang.ArithmeticException("Division by zero")`, and a signed `minValue / -1` or `minValue % -1` throws `ArithmeticException("Division overflow")`, with the class and line in the stack trace:

  ```
  try { var share = total / count } catch (e: ArithmeticException) { e.message.println() }
  ```

  `amlc test` checks; `amlc build` and `amlc run` don't, and divide exactly as before (a division is no throw site there, so throws inference is unchanged). A build target's `checkedDivision: true|false` in `package.yml` overrides the default either way. A literal divisor other than 0 (and other than -1 for a signed type) is never checked; `Float`/`Double` division is unchanged. Any division can then throw, so a checked build ignores `#noThrow` on non-native functions: ThrowsAnalyzer neither checks the contract (nor the rule that an override of a `#noThrow` function must not throw) nor counts anything against it, a division by a variable is a throw site (`RuntimeThrowSites.divisionCheckAt`, the predicate the renderer uses too), and every non-native function keeps the function_result ABI (`usesDirectNothrowAbi`, `skipExceptionCheckFor`, `canUseDirectNothrowCall`, `directWrapperNeeded` key on the checked mode, not only on test mode). A `#noThrow` function with an uncaught division compiles and throws under `amlc test`. Natives keep their ABI and a native's `#noThrow` is still trusted. In an unchecked build `#noThrow` is enforced as before. Needs am-lang-core 0.16.0 (`ArithmeticException`, `__throw_arithmetic_site`). v2 does the same. Docs: 02-syntax-grammar.md (Integer division by zero, per-platform behaviour of an unchecked build) and 16-compiler-usage.md (Checked division). Tests: DivisionCheckRenderTest (checked and unchecked C, literal divisors, compound forms, #noThrow ignored in a checked build and enforced in an unchecked one, no direct ABI in a checked build, throws inference, the flag and its package.yml key), am-lang-core DivisionCheckTests (13, under v1 and v2).
- **Array literals hold any expression, and nest** (Redmine #193). `var a = 5` then `var xs = [a, 2, f(3)]` failed with "Can't inject as operator on expression without evaluating expression 'init_array'" (since #187: "array literals hold constants only"), and so did enum values, calls and parameters; even `var c = [1, 2, 3]` without a declared type failed. Elements may now be locals, parameters, calls, enum values, `new` objects, string concatenation and `null`, evaluated once each, left to right; the array retains its object elements. The element type is the declared type when there is one (`var xs: Long[] = [a, 1]`, a parameter's type for `f([a, 1])`, a return type, a property's type), otherwise the elements' common type: same-signedness integers widen (`[i, 3L]` is `Long[]`), `Float` with `Double` is `Double`, objects widen to a shared base class or interface, and a `null` element makes it nullable (`["y", null]` is `String?[]`). An empty literal, one of only nulls, or elements with no common type (`["a", 1]`, `Int` with `UInt`) are errors that ask for a declared type, and an element that doesn't fit a declared type (`var s: String[] = [1]`) is "Array literal element of type Am.Lang.Int doesn't fit an array of Am.Lang.String". Nested literals make arrays of arrays: `[[1, 2], [3]]` is `Array<Array<Int>>`, now also written `Int[][]` and allocated with `new Int[][n]`. A bare call in an element (`[f(1)]`) was looked up on the array type; it is a call on the enclosing class. The C for an all-constant literal is unchanged (`__create_array` and one store per element; checked byte-identical). v2 handles everything except nested literals and `Int?[]`, which it doesn't have yet (clear errors there). Tests: ArrayLiteralTest (maven), am-lang-core ArrayLiteralTests (v1 and v2, with a live-object count) and examples/array-literals-v1 (nested and `Int?[]`, v1 only).
- **A `when` used as a value over an enum needs no `else` when every member has a branch, and its subject can be any expression** (Redmine #192). `fun name(c: Color): String = when (c) { Color.Red -> "red"; Color.Green, Color.Blue -> "cool" }` (one branch per line) compiles without `else`. Leaving a member out is an error on the `when` line that lists what is missing: "`when` used as a value doesn't cover every value of `Color`: missing `Color.Blue`. Add a branch for each, or an `else` branch". So adding a member to an enum later finds every value `when` that must handle it, where an `else` would have hidden it. A nullable enum subject (`Color?`) also needs a `null` branch. Without `else` the last branch is taken when nothing earlier matched, so the value is always defined. A non-enum subject, a `when { … }` with no subject and `is` branches still need an `else`; the error now names the subject's type. The subject no longer has to be a plain variable: `when (next())`, `when (h.inner!!.color)` evaluate it exactly once, into a hidden local declared where the value is computed, so it isn't evaluated when a `&&` short-circuits past it and is evaluated again on each pass through a loop condition. A `when` after `&&`, `||`, `<`, `[` or a comparison is now read as a value too, and a value `when` nested in another's branch stays a value. Statement-form `when` is unchanged: no `else` and no match does nothing. Tests: WhenStatementTest (6 new: exhaustive, missing members, missing `null`, non-enum and subject-less need `else`, `is` needs `else`, the call subject rendered once); am-lang-core WhenValueTests (12, also under v2).
- **Labeled loops: `break@name` and `continue@name`** (Redmine #164). A loop labeled `outer@ for (...)` (also `while`, `loop` and both `each` forms) can be left or continued from inside nested loops:

  ```
  outer@ for (i = 0 until n) {
      for (j = 0 until m) {
          if (grid[i * m + j] == target) { break@outer }
          if (skip(j)) { continue@outer }
      }
  }
  ```

  The jump unwinds like `return`: it sets the target loop's break or continue flag and leaves block by block, so every block on the way releases its objects, a `finally` runs, and a `for`'s counter advances on `continue@outer`. It works in suspend functions too. Errors, with file and line: an unknown label ("Unknown loop label 'x' in break@x: no enclosing loop is labeled x@"), a label on a statement that isn't a loop, a nested loop reusing an enclosing loop's label, and a jump to a loop outside the lambda it is in. The syntax is contextual: `outer` stays usable as a name, and a lambda may reuse the label of the loop around it. A plain `continue` outside a loop is now a compile error ("Continue statement not allowed here", as for `break`); it used to crash the renderer. On the way: a `break` or `continue` in a `switch` case followed by another `case` or `default` failed to parse ("Expected argumentsStart but found colon"). Tests: LoopLabelTest (maven), am-lang-core LoopLabelTests.

- **Nullable enums: `Color?`** (Redmine #237). An enum is stored as its backing value, so a nullable one is now a `nullable_value` with a null flag, the same as `UByte?`: `var k: Color? = null` is null and not the member whose value is 0 (`k == Color.black` is false), and `k != null`, `k!!`, `k ?? Color.white`, `k?.getValue()` work. So do `Color?` properties, parameters, returns, `List<Color?>`, `HashMap<K, Color?>`, `new Color?[n]` (all null), `Box<Color?>` beside `Box<Color>`, data class fields, lambda captures, `when` and suspend functions. A generic `T?` slot holding an enum (`HashMap<K, Color>.getOrNull` on a missing key) is null instead of reading 0. Before, `Color?` was an error (#161), as were comparing an enum with null and `null` in a `T?` holding one (#238). A plain enum is unchanged: `null` in one is the usual "Cannot assign `null` to non-null type" error, comparing it with null is constant, and a property without an initializer still starts as the first member (a `Color?` one starts as null). Tests: maven NullableEnumRenderTest (4) and BindingRegressionsTest (the three #161/#238 error tests replaced by four), am-lang-core NullableEnumTests (13, v1 and v2) and tests-v1-only/NullableEnumV1Tests (14; v2 gets these wrong for `Int?` too).
- **Path style conversion in `Am.IO.File`** (Redmine #380). `File.fromUnixPath("./data/../assets")` gives the host's form of a path written once in source: `assets` on AmigaOS, AROS and MorphOS ("." is "" there, ".." an empty part, a leading "/" the volume root ":"), `.\\..\\assets` style with "\\" on Windows and DOS, the path untouched on Unix. `toUnixPath` goes back, for a config file or a URL, and `fromAmigaPath`/`toAmigaPath` and `fromWindowsPath`/`toWindowsPath` do the same for the other two styles. A root with no form in the target style (`Work:x`, `C:\\x`, `\\\\server\\share`) gives null. `File.convertPath(path, fromStyle, toStyle)` converts between any two styles on any host, and `File.getPathStyle()` says which one the host uses (`PathStyleUnix`, `PathStyleAmiga`, `PathStyleWindows`). The conversion is textual: ".." stays a parent step and is never resolved against the name before it. `File.list()` now joins through `joinPath`, so listing `""` gives relative names rather than "/name".
- **`TaskScheduler.runAsync<T>(threadType, work)`** (Redmine #299). A suspend function runs `work` on a worker thread and resumes on its own thread with the result: `var s = TaskScheduler.runAsync<Socket>(TaskThreadType.IO, () => Socket.connectNow(host, port))`. Before, the only way was to capture the continuation in the scheduled lambda, which the isolate runtime rejects ("not sendable"): a continuation belongs to its thread. Now the continuation waits in a per-thread table and the worker sends the result (or the exception's message, rethrown as an `Exception`) back as a `Task`. The main thread must pump `TaskScheduler.handleMainTasks()`. The v2 compiler can't compile callers yet (#301).
- **`String.compareTo(other)`, and a warning for a signed and an unsigned integer in one operator** (Redmine #185, #186). `"apple".compareTo("banana")` is negative, 0 for equal strings and positive otherwise: byte-wise on the UTF-8 form (code point order), locale- and case-sensitive, a prefix first. `m == u` with `m: Int` and `u: UInt` warns "'==' mixes Int and UInt: the Int is converted to UInt, so a negative value wraps (-1 becomes 4294967295); convert one side explicitly", because C converts the signed operand: `-1 == 4294967295UI` was true without a word. It applies to comparisons and arithmetic where the unsigned type is at least as wide as the signed one after C's integer promotion (Int or Short with UInt, anything with ULong); Long with UInt, and UByte/UShort with anything, are safe and not reported, and neither is a non-negative literal on the signed side (`u < 10`). Existing code gets a handful: am-lang-core 20 (mostly `i < array.length()`), am-script 2, am-ui 3, am-cc 8, am-ide 54.
- **Lambda parameters can declare their types: `var f = (x: Int) => x * 2`** (Redmine #189). `(x: Int) => …` was a parse error ("Lambda parameters can't have types"), so a lambda in a local or field without a declared function type couldn't be written. A parameter may now carry a type as in a signature (`List<String>`, `String?`, `(n: Int) => Int`). With no function type to take (an untyped local or field), the declared types and what the body returns are the lambda's type: `f(3)` and `f.run(3)` work, `var g = (n: Int, s: String) => { return s + n.toString() }` is `(n: Int, s: String) => String`, and no returned value makes it `void`; returned values of different types are an error. Where a function type is expected (a typed variable, field or parameter), the declared types must be the expected ones, or it's an error naming the parameter and both types: `var f: (x: Int) => Int = (x: String) => 1` gives "Lambda parameter 'x' is declared String, but the function type it is used as expects Int" on the lambda's line (also for `Int?` against `Int`, `List<Int>` against `List<String>`, and a differing parameter count). Mixed `(a: Int, b) =>` takes the missing types from an expected function type; with none it is an error ("Lambda parameter 'b' has no type, and nothing gives the lambda a function type"). An untyped `var g = (x) => …` or `() => …` stays the #367 error. Overloads can't differ only in a function-type parameter, so declared types don't choose between overloads in v1 (v2 uses them to pick the lambda's callee). Not breaking: this was an error. Tests: TypedLambdaParamsTest (10, including a render check that the lambda's `run` takes an `int`); BindingRegressionsTest.aTypedLambdaParameterNamesTheRule now checks the message for a `:` with no type; am-lang-core TypedLambdaTests (12, also under v2). Maven 329/329, am-lang-core 338/338 (v1 and v2), am-tests 11/11.
- **Short lambda forms.** An expression body returns its value when the function type has a return type, `(x) => x * 2` instead of `(x) => return x * 2` (before, it failed with "Not all code paths returns a value: ..._INNER_1.run"), and a single parameter needs no parentheses: `x => x + 1`, `list.filter(n => n > 1)`. For a `() => void` type an expression body is run as a statement: `twice(() => counter.add())` (#188).

### Changed

- **AmigaOS and MorphOS: a thread that never stops during an out-of-memory shutdown is removed after 10 s** (2026-11-19, Redmine #446). Main waits 10 s there (3 s elsewhere) for the other threads, then removes the Exec task of each one still running (`RemTask`) and prints `Thread 'name' did not stop within 10 s; removed`, instead of exiting with the task still running in the unloaded program. What it held leaks (stack, objects, open files stay locked). Exit status stays 20. Runtime only (am-lang-core `core.c`); docs: 10-functions.md and 11-threading.md. Tests: am-lang-core `examples/OomShutdown/run.sh --amiga` runs the `busy` mode under amiberry, and the shell keeps working afterwards.
- **Breaking: running out of memory shuts the program down instead of throwing `OutOfMemoryException`** (2026-11-18, Redmine #446). Every `new`, array literal and string template counted as a throw site, because the exception could be caught, so nearly every function was "can throw": it lost the fast `__direct` call, and a `#noThrow` `toString`/`hash`/`equals` override needed a `try`/`catch` around any allocation (since #420). Now out of memory is fatal, as in Rust, Swift and Go. The thread that runs out prints `Out of memory allocating <class>` (stderr; stdout on AmigaOS) without allocating and `longjmp`s to its cleanup: on the main thread that is a new shutdown block in `startup.c` (a `setjmp` right after the emergency exception is reserved); a worker tears itself down and asks main to shut down. Main stops the other threads (they see it at `receive`, `join`, `sleep` and every `new`), waits up to 3 s for them, runs the normal exit sequence (`#runOnExit` hooks, statics, sweep, class shutdowns) and exits with 1, or 20 (`RETURN_FAIL`) on AmigaOS. Out of memory during that shutdown skips the remaining exit hooks. `ThrowsAnalyzer` no longer counts `new`, `init_array` or string templates; `new T[n]` still throws when `n` isn't a non-negative constant or unsigned (negative size). So `override fun toString(): String { return "Node ${this.name}" }` compiles without a `try`. `OutOfMemoryException` stays for source compatibility, but `catch (e: OutOfMemoryException)` and `is OutOfMemoryException` no longer see an allocation failure. The frames that were running are not unwound: their `finally` blocks don't run and objects only they held are not released (a `TRACKOBJECTS` build reports them). The test runner (`amlc test`) counts an out-of-memory test as a failure and ends the run. Needs am-lang-core 0.16.0 (`AMLC_OOM_SHUTDOWN`); with an older core the startup builds without the jump target. Tests: `OomShutdownTest` (analyzer verdicts, `__direct` ABI and the stop point on an allocating function, the rendered `setjmp` and shutdown/emergency labels), `TestRunnerRenderTest.outOfMemoryEndsTheRunAsAFailure`, core `NoThrowAllocationTests`, and the real programs in am-lang-core `examples/OomShutdown` (`run.sh`: out of memory on main, in a worker while others wait in `join`/`sleep`/`receive` or spin, during the shutdown; exit codes and which exit hooks ran), passing on linux-x64 and on AmigaOS under amiberry.
- **Breaking: `<`, `>`, `<=` and `>=` on two strings are an error** (Redmine #185). They compared the strings' addresses, so `"banana" < "apple"` depended on allocation order, and sorting code such as `x.label < y.label` compiled and sorted wrongly. The error reads "Strings can't be compared with < (it would compare their addresses); use a.compareTo(b) < 0". `==` is unchanged (it calls `equals`). Of the AmLang projects only am-ide is affected: `HighlightedTextEditor.entryBefore` sorts completions this way.
- **Breaking: a test run in which no test ran fails.** The runner printed "All tests PASSED!" and exited 0 when it ran nothing, which hid a build that lost its tests (see the treeShake fix below) and a class or method name on the command line that matched nothing. It now prints `Error: no tests were run` and exits 1. A package with no tests must not be run with `amlc test`.
- **A `#noThrow` native's direct-call adapter is `static inline` in the class header.** Callers of a `#noThrow` native call `<name>__direct`, which unpacks the native's `function_result`. It was an out-of-line function in the `.c` file for every class variant, kept even when nothing called it and with `treeShake`: `Array.createEmptyArrayOfSameType` alone added about 4.6 KB to a mid-size program. Now an unused adapter costs nothing and a used one inlines (Redmine #183).
- **Warnings are printed on every build, test and lint, not only when the build fails.** Before, collected warnings (obsolete functions, `'const var' is deprecated`) appeared only in a failing build's report, `amlc lint` showed none, and warnings raised while parsing were discarded before binding, so they never appeared at all. Now the package's own warnings are listed, sorted by file and line, after analysis and before the C build, with a count; the dependencies' warnings are a one-line count. `-wdeps` lists those too, `-nowarn` hides all (#210).
- **Breaking: hex literals take no type suffix, and `B` in a hex literal is always a digit.** `B` was read as the Byte suffix, so `0x1B` was silently the Byte 1, not 27 (as was `0x5B`, `0x7B`, `0xFB`...); now `0x1B` is 27 and `0x80B` is 2059. Any suffix on a hex literal (`0xFFUI`, `0xffUB`, `0x10L`, `0x7fffS`) is an error that names the `as` form. Hex literals take their type from where they are used (`var m: UInt = 0xFFFFFFFF`, `ub == 0xFA`, an argument, an array element), `as T` where nothing says it, and a hex literal wider than 32 bits is a Long (`0x100000000`) or, when it doesn't fit one, a ULong (`0xffffffffffffffff`); before, those needed `L`/`UL`. To migrate: drop the suffix where the literal is assigned to, compared with, or passed as a typed value; elsewhere write `(0x80000000 as UInt)`. Deleting a suffix where nothing gives the type changes it to Int (`var m = 0x80000000UI` would become a negative Int). Decimal suffixes (`255UB`, `100L`) are unchanged. v1 and v2 (#184).
- **Breaking: build output is per build target, in `builds/<targetId>/`.** Each target gets its own tree with a plain `Makefile`, its generated C and `bin/` (`bin/app`, objects in `bin/o`), instead of every target sharing `builds/` with a `<platform>.makefile` each and `bin/<platform>/`. Two targets on the same platform used to share an object directory, so switching between them silently reused the other's `.o` files. Test builds follow suit (`test-builds/<targetId>/test-bin/test_app`), and `sshBuild` targets work from `builds/<targetId>`. `amlc build .` without `-bt` now only parses, binds and validates; a package with no `buildTargets:` still renders the single legacy `builds/` tree. Scripts that read `builds/bin/<platform>/app` must use `builds/<targetId>/bin/app`.
- **Git dependencies are fetched with the system `git` instead of JGit.** `amlc` runs `git clone --depth 1 [--branch <b>]` (and `git -C <dir> pull` with `-fld`), so `git` must be on `PATH`; `-git-path <path>` names another executable, as in v2. Realm credentials are passed as an `http.extraHeader`, so the token stays out of the clone's `.git/config` and URL. A dependency without a tag is cloned into a `latest` folder (was `null`). The JGit library is gone from the jar.
- **Breaking: an override of a `#noThrow` function whose body can throw is a compile error that says where and why** (2026-11-18, Redmine #420, follow-up). `toString()`, `hash()` and `equals()` are `#noThrow`, and since #420 counts the null check on a member access, `op=` on a nullable primitive and array bounds checks as throw sites, an override such as `override fun toString(): String { return this.next.toString() }` (`next: Node?`) is rejected; the override must catch, with `try { ... } catch (e: Exception) { ... }` around the code that can throw (a narrower catch doesn't count). This holds for direct overrides, overrides several classes down, interface implementations and generic classes. The message names the override's file and line, the nearest `#noThrow` function it overrides and the first throw site with its kind and line: "'App.Node.toString' overrides #noThrow function 'Am.Lang.Any.toString' and can throw: null check on member access `this.next.toString()` at line 6. An override of a #noThrow function must not throw: catch it with try/catch (catch (e: Exception)) around the code that can throw." (It used to say "member access through 'next', which can be null, is null-checked (line 6)" and suggested dropping `#noThrow` from the base, which an override can't do.) Two gaps closed on the way: an override whose own throw site was found only after a sibling override had made the whole chain "throwing" got no error of its own, and a generic class nobody instantiates got false errors from its unbound template body (never compiled; now skipped). Generated data-class members keep their catch-all. Tests: NoThrowOverrideTest (10: each override kind, the message parts, a catch-all compiles, a narrower catch doesn't, non-throwing overrides compile, every throwing override reported once, an uninstantiated generic class, an own `#noThrow` function). v2 doesn't check `#noThrow` yet (V2_PORT_PLAN.md).

### Fixed

- **An assignment statement's own new temp is released right after the statement, and a reassigned local retains the new value before it releases the old** (2026-11-22, Redmine #600). `b.kid = new Box()`, `T.s = make()`, `arr[i] = new Box()` and `x = new Box()` kept the statement's extra reference to the value until the block (in straight-line code, the function) ended, so each replaced value lived on: three `b.kid = new Box()` in a row left three objects. #583's release of a statement's own temps (discarded calls, loops) now covers plain assignment statements (`CRenderer.isPlainAssignmentStatement`); the stored value keeps the reference the property, static, element or local took. A compound assignment is left as it was. That release exposed a use-after-free the leaked reference had hidden: an `Any` or object local assigned from itself (`r = r`) released the old value, which could be the only owner, before it retained the new one; the local assignment now saves the old value, retains the new and then releases the old. Tests: `AssignTempReleaseRenderTest`; am-lang-core `AssignTempTests` (allocation counts right after straight-line stores to a property, `this`, a chained receiver, a static, an array element and a local; values still readable) under v1 and v2.
- **`==`, `!=` and `!!` after a safe-call chain apply to the chain's result, which is null when any link is** (2026-11-22, Redmine #596). The parser appends the operator to the chain's tail, so it rendered inside the chain's `if (link != NULL)` branches, and a null link left the chain's NULL as the result, read as `false` or `0`: `z?.n == null` with `z` null, `a?.kid?.n == null` and `a?.kid?.n != 7` with `kid` null, and `none?.s == null` with `none` null were all `false`, and `a?.kid?.n!!` gave `0` instead of throwing. The binder now cuts such a chain before the operator, as if written `(a?.kid?.n) == null`, and a group around a safe chain is typed with the chain's result (`(z?.n)` is an `Int?`; it was the tail's `Int`, so `(z?.n) == null` was false too). `??` was already applied to the result; assignments through a chain (`a?.s = v`) and other operators are unchanged. A comparison where every link is set gives the same result as before. Tests: SafeChainComparisonTest (the cut, the group's type, `??` and plain chains not cut, no comparison stored in a chain's result); am-lang-core SafeChainResultTests (+6: Int, Bool, enum, String and object results with a null at the start, in the middle and at the end; `==`, `!=`, `== value`, `!!` throwing, `??`, in `if` conditions and assigned to locals) and SafeCallTopValueArcTests (+5 positions with allocation counts: a null check assigned to a local, `!=` on a value only the chain owns, `== "qq!"`, `!!` and a null in the middle; `null?.s == null` is now checked), under v1 and v2 (v2 already gave these results since #592).
- **A mixed-width sum has the wider operand's type: `before + 1` with `before: Long` is a Long** (2026-11-22, Redmine #599). `Long + Int` took the type of its right operand (Int), so `var n = before + 1` was an Int local holding a sum truncated to 32 bits, and `Assert.assertEquals(before + 1, Arc.getAllocationCount())` boxed it with Int flags and failed with "expected '1488', got '1488'" (Any equality compares the type bits, #562); `before + 1L` and `1 + before` worked. The result of an arithmetic or bitwise operator is now the operand with the wider storage in either order: Double over Float over the integers, and among the integers the larger one (`Long + Int`, `Int + Long`, `Short + Long`, `UInt + Long` are Long, `Byte + Int` is Int, `Int + Double` is Double); operands of the same width keep the right operand's type, as before. A sum assigned to a narrower declared type is a conversion at the assignment, as it already was for `Int + Long`. Tests: `MixedWidthSumRenderTest` (the C type of each combination and of `a + b + c` chains), am-lang-core `MixedWidthArithmeticTests` (the type through overloads on Byte/Short/Int/Long/UInt/Float/Double, sums passed to `Any` and compared with `==` and `assertEquals`, values above 2^32).
- **A safe-call value used as an argument, a return value, a template part, a `??` operand or a dropped statement no longer leaks** (2026-11-22, Redmine #595). A `?.` chain's top variable holds a reference of its own; #589 released it after a property or array store, but `take(maybe(o)?.s)`, `return maybe(o)?.s`, `f(maybe(o)?.s)` with a lambda, `x ?? maybe(o)?.s`, `maybe(o)?.s ?? maybe(p)?.s`, `(maybe(o)?.s)`, `if (c) maybe(o)?.s else null` and a statement like `maybe(o)?.kid?.me()` still leaked the value every time (10 objects per 10 runs; a null receiver didn't leak). A consumer that only borrows the value now hands that reference to a temp of the enclosing block, released at its exit (and saved across a suspend point with the block's other temps); one that takes its own reference (the if-expression result, a `??` fallback, a dropped statement) releases it on the spot. Two neighbouring bugs are fixed too: a string template part ending in a safe call (`"v=${o?.s ?? "z"}"`, `"${maybe(o)?.s}"`) didn't compile (it read a temp of the `?` branch; it reads the top variable now), and a safe-call argument of a suspend call (`this.parkStr(maybe(o)?.s)`, `this.parkInt(o?.n ?? 5)`) reached the callee as null or 0, because the child state took the `?` branch's temp, already released and NULLed. Comparisons (`maybe(o)?.s == null`), `when` subjects and local declarations didn't leak and are unchanged. All of these are now compile errors with file and line, for arguments, assignments, properties and returns, also through a subclass with fixed arguments (`class IntBox: Box<Int>`) and through interfaces: "Unable to convert Int[] to Long[]: its Int elements are stored differently from Long, and nothing converts them when the array is passed on; copy it element by element into a new Long[], or declare it as Long[] from the start", and for objects "Unable to convert List<Dog> to List<Animal>: a List<Animal> may be given any Animal, which this List of Dog would then hand out as a Dog; …". Still allowed: a scalar `Int` where a `Long` is expected (converted as before), an array literal argument (typed from the parameter since #193), generic inference (`firstOf<T>(xs: T[])` with an `Int[]`), the other signedness of the same width (`Byte[]` as `UByte[]`, `Int[]` as `UInt[]`, which reads the same bits a converted copy would hold; am-ssl and am-web-client do this), and `List<String>` as `List<String?>`. An explicit `a as Long[]` was and is a runtime "Can't cast" exception. None of the AmLang projects is affected (all 50 validated before and after; the hex-suffix migration was applied to the copies first). v2 still accepts all of these (it compares no type arguments at all); recorded in V2_PORT_PLAN.md. Tests: GenericNumberArgumentTest (12).
- **A null `Int?` compared with a value read stack garbage, and `new Int?[n]` elements read as 0** (found with #237). `n == 5` with `n: Int? = null` declared the result without a value and set it only when `n` held one, so the outcome was whatever was on the stack; a null that kept its type bits compared its old payload. It now starts false and skips a null. An element of a fresh `Int?[]` (zeroed memory, no flags) read as a non-null 0; a slot with no type bits now reads as null, in `== null`, `!!`, `?.`, `??` and conversions.
- **A suspend function with an `Int?` (or `Color?`) parameter, local or return value didn't compile.** The state saved across the suspension restored a nullable value as its bare payload ("incompatible types ... nullable_value"), and a non-null enum return was assigned to an undeclared temporary. The whole `nullable_value` is restored now.
- **A lambda created in `init` captures `this`.** `init { this.cb = () => this.n * 3 }` failed in gcc ("initializing aobject * using nullable_value"): in `__init_instance` (and in a primitive's methods) `this` is boxed, and the capture copied the box. It now captures the object. New test: am-lang-core LambdaTests.thisInsideLambdaIsTheEnclosingInstance.
- **A lambda passed to an explicitly generic static call builds.** `TaskScheduler.runAsync<Int>(() => ...)` failed with "Namespace not found: " because a class without a namespace was imported into the lambda's class. Blank namespaces are skipped.
- **A lambda in an untyped local is a compile error instead of a compiler crash** (Redmine #367). `var g = () => 1` gives the lambda nowhere to take its function type from, and amlc stopped with a bare `NullPointerException` and no file or line. It is now reported on the lambda's line: declare the type (`var g: () => Int = () => 1`) or pass the lambda where a function type is expected. Lambdas in property initializers, typed locals and arguments are unaffected.
- **Every `init { }` block runs, in source order with the property initializers** (Redmine #25). A class with `init` blocks but no properties skipped them entirely in v1: it was treated as having nothing to initialise, so neither `init` block in `class C { init { a() } init { b() } }` ran. v2 kept only a class's last `init` block and ran it after all the property initializers. Both compilers now run construction in one order: the primary constructor's parameters, then property initializers and `init` blocks top to bottom as written. The order is documented in 06-classes-objects.md.
- **A suspend fun call no longer leaks its receiver and object arguments** (Redmine #336). A `suspend fun` retained `this` and each object parameter when it started and never released them, so every call left its object (and, say, a `String` argument) alive for the rest of the program. They are now released when the function completes, which is after the last resume for a function that suspends, so a caller may still drop its own reference while the call is parked.
- **An exception thrown inside a `suspend(cont) { }` block reaches the caller** (Redmine #298). `suspend(cont) { throw new Exception("x") }` released `cont` without a resume, which fired a `ContinuationCancelledException` into the suspended function: the caller caught "Continuation cancelled — dropped without resume()" instead of `x`, and the throwing frame then used the freed suspend state and segfaulted. A `throw` or `return` leaving the block now claims the continuation first, so the real exception (or return value) propagates and a later `cont.resume()` of a copy handed out in the block does nothing. If the block already called `cont.resume()` before throwing, the resumed function has moved on and the exception is dropped.
- **A value computed before a suspend call in the same statement survives the suspension** (Redmine #35). In `this.total = this.total + this.fetch()` or `this.client.count = this.fetch()` inside a `suspend fun`, the parts evaluated before the call (`this.total`, the receiver `this.client`, a function pointer for `+`) were C temporaries that weren't saved when the function suspended. It resumes through a fresh C call that jumps past them, so they held whatever was on the stack: a wrong sum, or a write through a garbage pointer, which crashed. At -O0 the stale stack slot often still held the right value, so it showed mostly in optimised builds, and only when the call really suspended. This is what am-ide hit (`if (this.agentMode)` reading false, field writes not sticking). Those temporaries are now saved with the suspend state and restored on resume. New test: am-lang-core SuspendTempTests.
- **A static initializer's error is no longer lost when its first read is an argument of an overloaded call** (Redmine #162). The read binds the initializer on demand while the compiler tries the overloads; the first error ended that attempt part-way, and the half-bound initializer was never bound again, so only "Argument expression has no evaluated type" and "Function not found" were reported. It is now bound again afterwards and its own error comes first. It depended on the order classes are bound in (by name: `Areader` reading `Zowner.x`).
- **Clearer messages for common mistakes** (Redmine #187). An `override` whose return type differs from the base's said "Function value not found in base class"; it now says "value overrides Base.value(): Int but returns String: an override must return the same type", and different parameters name the base's signature. An array literal holding a variable or call said "Can't inject as operator on expression without evaluating expression 'init_array'"; it now says array literals hold constants only and to use `new T[n]`. `val k = 5` adds "AmLang declares a local with var". A typed lambda parameter, `(x: Int) => …`, said "Unexpected expression: :"; it now says lambda parameters can't have types. (`(x) => x * 2`, `x => …` and `"$0"` from the same report already worked.)
- **Every `namespace` block in a file is compiled, not only the first** (Redmine #274). The parser stopped after the first block and ignored the rest of the file without a word: `namespace Lib { class Box { … } }` followed by `namespace R { class Program { static fun main() { … } } }` built a program without `main` that ran, printed nothing and exited 0. The self-hosted v2 compiler already compiled every block. No file in the AmLang projects has more than one namespace, so existing code is unaffected.
- **An interface or enum sees `Am.Lang` without an import, as a class does.** Only classes and structs got the implicit `import Am.Lang`. An interface that no class implements, with `Exception` (or any other non-primitive Am.Lang class) in a signature, left that type unbound without an error, and rendering crashed with `Void type in function parameter: Exception`. When a class implemented it, the signature happened to bind through that class. The self-hosted v2 compiler resolves names the same way (#271). Nothing to change in existing code.
- **`amlc test` with a `treeShake: true` build target ran no tests.** Tree shaking kept only what `main()` reaches, so the test classes were removed, and the runner printed `Final Results - Passed: 0, Failed: 0` and "All tests PASSED!". Classes with `test` functions are now kept.
- **The test runner's coverage count no longer stalls `gcc -O2`.** `test-startup.c` counted coverage per class with one `if` per coverable expression written out in `main()`: about 18,000 lines for the v2 compiler's tests, which gcc 15 at `-O2` didn't finish compiling in an hour. It is now a constant table from expression to class and one loop. The coverage report is unchanged (Redmine #261).
- **`open class` is accepted.** It failed with "Unexpected keyword ... \"open\"", although v2 accepts it. Every class can already be subclassed, so it changes nothing. `open` is a modifier only before `class` or `fun`; as a property, method, local or parameter name it works as before (Redmine #265).
- **Conditions of `if`, `while` and `each` are validated like any other expression.** They were only checked for being a Bool, so a mistake inside one passed: `if (h.count > 0)` with `count` private in another class compiled, while `var n = h.count` was rejected. All projects in ~/Projects/AmLang validate as before (Redmine #264).
- **A local typed with a class whose namespace isn't imported now gives one error that names the import.** `var l: List<String> = Maker.make()` in a class without `import Am.Collections` gave 13 errors ("Unable to convert Am.Collections.List<Am.Lang.String> to List<Am.Lang.String>", "Method 'getSize' not found", "evaluatedType not resolved", ...), none of which mentioned the import, and in a test file it crashed the binder. It now reports "Type of 'l': class 'List' was not found: it is in namespace 'Am.Collections'; add 'import Am.Collections' to class 'Program'", and nothing else for that code (Redmine #269).
- **A call on a class whose namespace isn't imported now names the import.** `var ints = new List<Int>()` without `import Am.Collections`, followed by `ints.getSize()`, reported only "Function 'getSize' not found on type 'List'", as if List had no getSize, and the binder error stopped the build before the validator's own "add 'import Am.Collections'" message for the `new`. The error now ends "— class 'List' was not found: it is in namespace 'Am.Collections'; add 'import Am.Collections' to class 'Program'" (Redmine #254).
- **An undefined name was reported as "Unknown error".** `var s = "a " + nope` gave "Unknown error", "Can't inject as operator on expression without evaluating expression 'a '" and, at the next use of `s`, "Variable 's' has no type assigned during binding" — none naming `nope`. It is now one error, "`nope` is not defined here (no local, parameter, property or class of that name)", and the errors that only followed from it on that line, or from using `s` afterwards, are dropped. A missing member says so too: "`nope` is not a member of Int", "`x` is not a static member of Owner". A failed build no longer prints the binder's stack traces or a Java stack for "One or more errors"; `-ll3` prints them (Redmine #250).
- **A static function of a generic class that used the class's type parameter crashed the compiler** with a bare `RuntimeException: T` and no file or line (`class Box<T> { static fun wrap(x: T): Box<T> }`). It is now an error at the function: a static function has no class type arguments; give it its own, `static fun wrap<T>(x: T): Box<T>`, called as `Box.wrap<Int>(3)` (Redmine #249).
- **Calling another class's private function said "not found".** `Owner.secret()` with `secret` private reported "Function 'secret' not found on type '__StaticMemberAccessor'" (an internal name), and `o.inner()` "not found on type 'Owner'". Both now say "'secret' is private in Owner". A private property read from another class was reported twice; the same error on the same line is now recorded once (Redmine #37).
- **A stray word in a class body compiled silently.** A typo on its own line between members (`dadsad`) was skipped; it is now an error naming the word, the class and the line. `public` before a member is still accepted and still means nothing (members are public by default). The self-hosted v2 compiler still skips such words; am-compiler-lsp reports them in the editor (Redmine #178).
- **`$` in strings: `"x $0"` failed with "Unknown error", there was no way to write `${` literally, and `${n + 1}` broke inside a concatenation.** `$` followed by something that can't start a name (`$0`, `$5`, `$ `) is now a literal `$`; `\$` is a literal `$` anywhere, so `"\${1:x}"` is the text `${1:x}`. `"a" + "${n + 1}"` cut the template's expression at its `+` ("Expected blockEnd but found plus"). A name in a template that isn't defined is reported as such instead of "Unknown error" (Redmine #179).
- **A generic `T?` slot instantiated with an enum rendered C that didn't compile.** `Box<Color>` with `var v: T? = null` stored `null` in what is, for an enum, its plain backing value. The slot is now a nullable enum and holds null as `Box<Int>`'s does; see "Nullable enums" under Added (Redmine #238, #237).
- **`f!!(args)` didn't call `f`.** A call of a nullable function-typed value through `!!`, such as `h.listener!!(1)`, parsed as `h.listener!!` followed by the group `(1)`: it evaluated to `1` without calling the listener, and with a chained call (`h.listener!!(1).toString()`) the compiler crashed with "Invalid conversion". It is now a call of the checked value; a null value throws NullAssertionError as before. The self-hosted v2 compiler didn't parse it at all and now does for properties; v2 still mishandles nullable function-typed locals (Redmine #239, #248).
- **A build target without a `features:` key turned on every feature.** With `availableFeatures: ["selftest"]`, a build target written without `features:` (meant as "none") compiled the `#require selftest` classes, dropped the `#requireNot selftest` ones and passed `-DFEATURE_SELFTEST`, logging "No build target specified - using ALL available features". A build target now enables exactly its `features:`, none when the key is missing, and a `-bt` the package doesn't declare enables none. A build with no `-bt` still enables every feature. Packages that relied on the old behaviour must list their features on the target (Redmine #247).
- **A class with an object property didn't build with gcc 6.5 (m68k-amigaos, ppc-morphos): "initializer element is not constant".** The constant image a class's properties start from wrote each slot as a compound literal, `(nullable_value) { .value = (value) { ... } }`, which older gcc rejects in a static initializer. It is now a plain brace initializer, which means the same.
- **A bare call on the right of a comparison or arithmetic operator was looked up on the left operand's type.** `return k == pick()` with `k` an enum failed with "Method 'pick' not found", and `n + two()` / `n > two()` the same way; worse, a bare call named like a method of the left operand's class (`other != toString()`) could silently bind to that method instead of `this.toString()`. The right operand is now an expression of its own, as `&&` / `||` operands already were (Redmine #160).
- **`Color?` (a nullable enum) compiled to C that didn't build, or read a 0-valued member as null.** An enum is stored as its backing value and `Color?` had no flag for null. It was briefly an error (#161); nullable enums now work, see "Nullable enums" under Added (Redmine #161, #237).
- **`list.map((x) => ...)` crashed the compiler.** A type parameter that appears only in a lambda's result type (`map<T, U>(..., mapper: (t: T) => U)`, or `make<U>(f: () => U)`) couldn't be inferred: binding died with a NullPointerException after "Generic type in function: U". The compiler now types the lambda's parameters from what the other arguments determine, works out the type of what its body returns, and takes U from that: `words.map((w) => w.length())` is an `Iterable<Int>`, chains and block bodies included. Returns anywhere in the body count (inside `if`/`else`, loops), lambdas inside the body are fine (`orders.map(o => o.items.filter(i => i.big).toList())`), returns of different types are an error naming them, and when U still can't be inferred it's an error that names the type parameter (#222).
- **An extension function didn't match a nested generic receiver.** `Iterable<List<Int>>.toList()` failed with "Function 'toList' not found on type 'Iterable'": substituting `T = List<Int>` into the extension's `Iterable<T>` dropped List's own type arguments (`Iterable<List>`), and only the first level of type arguments was substituted at all. `Generics.updateTypeFromTypeMap` now keeps them and substitutes at every depth, including function types.
- **A lambda passed to another class's function took that class's imports, file and capture chain.** `list.filter((w) => new TextParser(w)...)` failed when the receiving class (here `CollectionExtensions`) didn't import `TextParser`'s namespace, errors in such a lambda were reported in the receiver's file (at a line of the caller's), and a passed lambda inside another passed lambda couldn't read the method's locals (gcc: "'var_mid' undeclared"). The lambda now belongs to the class it is written in (`Program_INNER_n`, not `CollectionExtensions_INNER_n`); its parameter types still come from the receiver (#34, #33).
- **`() => Void` gave "Not all code paths returns a value: ..._INNER_n.run".** `Void` isn't a type (a function type that returns nothing is `() => void`); it was taken as a return type named Void. It is now an error that says so (#217).
- **Byte was unsigned on ARM and PowerPC.** Byte values were C `char`, which is signed on x86 and m68k but unsigned on ARM (Linux aarch64) and PowerPC (MorphOS, AmigaOS 4), so there `-128B` read back as 128, `b < 0B` was never true, and a negative Double/Float converted to a Byte was undefined. Byte is now `signed char` in generated code (v1 and v2) and in am-lang-core's natives. Hand-written natives that take a Byte parameter must declare it `signed char` (a plain `char` now gives "conflicting types"); none in the AmLang packages do (#209).
- **A platform only the app declares lost its dependencies' native sources.** With `release extends linux-x64` in the app's `package.yml` (a static or cross-compiled variant of a platform am-lang-core knows), `amlc build . -bt release` failed with `No rule to make target 'additional/am-lang-core/libc/core.c'`: the Makefile listed core's libc sources, but they were never copied, because the copy step ran before the dependencies were told about the app's platforms. `amlc test` on such a platform could leave a dependency's natives out entirely. Both now work as they do for a platform every package declares.
- **A member after `!!` or `?.` bound to a local of the same name.** In `tier = league!!.tier.toInt()` with a local `tier` in scope, `.tier` read the local: a "Function 'toInt' not found on type 'Int'" error, or, when the types fit (`t = league!!.tier`), a silently wrong value. The name after `!!` / `?.` is now always the member, as after `(x as T)` (#158).
- **A field initializer could not read another class's untyped static.** `var a: Int[] = new Int[Other.count]` or `var n: Int = Other.count`, where `Other` declares `static const var count = 5` without a type, failed with "Can't inject as operator…" or a bare NullPointerException with no file or line, depending on class order. The static's type is now inferred before it is read; a remaining case (two static initializers reading each other's untyped statics) reports the property, file and line and asks for an explicit type (#150).
- **A `for` loop whose start bound was a chained expression typed its variable wrongly.** `for (i = this.starts[t] until this.starts[t + 1])` typed `i` as the class of `this`, failing at its first use with "Invalid conversion between source var_i:aobject *". The variable now takes the type of the whole start expression (#148).
- **A method of an enum's backing type couldn't be called on a member.** `KeyColors.white.toInt()` for `enum KeyColors<UByte>` failed with "Invalid object reference: toInt"; it now calls `toInt` on the member's value, as `KeyColors.white.getValue().toInt()` does (#149).
- **An unknown function on the right of `&&` / `||` crashed the renderer.** `while (j > 0 && a.title.compareTo(b.title) < 0)` (String has no `compareTo`) died with a bare NullPointerException; it now reports "Function 'compareTo' not found on type 'String'" with its line (#106).

## [0.15.0] - 2026-11-07

Changes since v0.14.0.

### Changed

- **Breaking: `for (i = a to b)` now includes `b`; the new `for (i = a until b)` stops before it.** `0 to 3` runs with 0, 1, 2, 3 and `0 to 0` runs once; `0 until 3` runs with 0, 1, 2 — what `to` used to do. Existing loops that index with `to` (`for (i = 0 to arr.length())`) now run one pass too many. Every `to` loop in the AmLang projects has been rewritten to `until`, so their behaviour is unchanged; code elsewhere needs the same rewrite. A `to` loop whose end is a `size`/`length`/`count` read or call warns at compile time, on successful builds too. am-script scripts follow the same rule (`.amsb` cache version 19).

### Added

- **`requiredStack` on a build target.** `requiredStack: 65536` makes the program check its stack first thing at startup and, if it is smaller, print the size needed and exit with status 20 (Amiga family; ignored elsewhere). Needs am-lang-core with `__amlc_require_stack`; an older core builds without the check.
- **Function overloading by parameter type.** Functions may share a name and a parameter count when their parameter types differ, and a call picks the best match by the static types of its arguments: exact class, then nearest subclass, then numeric widening, then `Any` / generic / function-typed / null. Virtual and interface overloads dispatch at run time. Before this, the second declaration was rejected as "already exists", and every call bound to the first function with that name and count. See docs/10-functions.md.
- **`when` statement with smart casts.** `when (x) { is Circle -> … ; 1, 2 -> … ; !is T -> … ; else -> … }` and the subject-less `when { cond -> … }`. In an `is T` branch the subject is typed `T` without an explicit cast — for class, interface and `Any` subjects — including field writes through it. Branches run top to bottom, first match wins; a body is a block or one statement; the subject is evaluated once. `when` is a statement (using it as a value is a compile error) and stays usable as an identifier. See docs/03-keywords.md.
- **`data class`.** `data class Point(var x: Int, var y: Int)` gets generated `equals`, `hash`, `toString` (`Point(x=1, y=2)`) and `copy()` from its primary-constructor properties, so value comparison and hash-based collections work without hand-written `equals` / `hash` pairs. Members the class declares itself are kept; the body is optional; generic data classes work; `data` stays usable as an identifier. See docs/03-keywords.md.
- **`*=`, `/=`, `%=`, `&=`, `^=`** join `+=`, `-=` and `|=`, for locals, properties, statics, array elements, nullable primitives and classes with the matching operator function (`op /`, `op %`, ...).
- **Operator functions `op /`, `op %`, `op &`, `op |`, `op ^`** can be declared (they were rejected as "Operator not found").
- **`if` and `when` as expressions, and expression bodies.** `var s = if (x < 0) "neg" else "pos"` (no braces; `else` required; only the chosen branch runs; a `null` branch makes the type nullable). `when` works in a value position too (`return when (s) { … }`): single-expression branches, an `else`, a plain-variable subject. `fun area(): Int = this.w * this.h` is a function with an expression body. A braceless `if (c) a() else b()` also works as a statement. See docs/03-keywords.md and docs/10-functions.md.
- **Default parameter values and named arguments.** `fun label(text: String, size: Int = 12, bold: Bool = false)` can be called as `label("Hi")`, `label("Hi", bold = true)` or `label(bold = true, text = "Hi")`, and the same works for constructors (`new Pt(y = 7, x = 2)`). Defaults are constants (literals or `null`) and must come after the parameters without one; the caller fills them in. An exact-arity overload wins over one that needs a default. See docs/10-functions.md.
- **`const x: T` in a primary constructor is a read-only property**, like `var x: T` but constant after construction. `const var x: T` (the older spelling) still works.

### Fixed

- **`amlc test` starts coverage tracking before the out-of-memory singleton is created**, since creating it runs instrumented code; a coverage build crashed at startup.
- **`init { }` blocks and property initializers were never validated.** `new MissingClass()` there crashed the renderer with a bare NullPointerException, a type mismatch surfaced as an internal conversion error, and an unknown call (`init { A.nope() }`) built successfully with the call missing from the generated C. They now get the same errors as code in a function, with file and line. Code that was being silently dropped is now a compile error: am-ide, tucan-mail and tucan-paint each have such lines (#61).
- **`amlc test` ignored a platform's `linkerCommand`.** The test executable was linked with the C compiler and its compile options. A platform with a `linkerCommand` (its own or inherited) now links tests the way `amlc build` links the program. Platforms without one are unchanged.
- **`amlc test` compiled with only the target platform's own `gccAdditionalOptions`.** `amlc build` has always added a child platform's options to its parents' and to dependencies', minus `gccRemoveOptions`, plus enabled features' options. The test makefile now collects them the same way, so tests compile with the flags the real build uses.
- **A platform with no `gccCommand` called a command named `null`.** A platform that names no compiler now inherits its C compiler, assembler and linker commands from the platforms it extends, so `amigaos-minigl` can just say `extends: amigaos`. A build target with no compiler at all is reported up front.
- **A failed build left the previous executable in place.** `amlc build`, `run` and `test` now remove the selected targets' executable first, so a failed build can't be mistaken for a working one. Object files are kept, so builds stay incremental.
- **amlc exited 0 when it failed.** A compile error, a failed `make` / docker / ssh build, failing tests, an unknown command and a run whose program failed all ended with exit status 0, so scripts and CI saw success. They now exit 1. A `-bt` naming a build target the package does not define is now an error that lists the defined targets, instead of silently doing nothing, and one whose platform the package does not declare as a non-abstract platform (including a package.yml with no `platforms:` section, which threw a NullPointerException) is an error naming the declared platforms; `amlc test` checks this too (#56, #15, #16). Note that `amlc test` now exits 1 when any test fails.
- **`obj.p = a && b` emitted uncompilable C.** A property or static write whose value was a short-circuit `&&`/`||` read the right operand's temp from outside the block it was declared in (`use of undeclared identifier '__varN'` at `make`), and an array element write (`arr[i] = a || b`) assigned the boxed result to a `bool`. Both now store the expression's result, which is also correct when the left operand decides (#40).
- **Instance members without `this.`.** Calling an instance method without a receiver (`helper()` in an instance method) failed with "Function not found", a bare property as an operator's right operand (`2 * n`, `n = n + 1`, `var area = width * height` in a property initializer) was looked up on the left operand's type, and a bare property read on its own crashed the C renderer. All three now bind as `this.helper()` / `this.n`, as V2 already did; from a static function the error says "Instance function 'helper' can't be called from static function …". A local function value with the method's name wins for `name()`.
- **Static initializers ran before the statics they read.** `static var a: Int = B.b + 1` read 0 (or crashed on a NULL string) when class `A` happened to initialise before `B`, and `static var c = d * 2` above `static var d = 5` read 0. Classes now initialise after the classes their static initializers reference (static reads and calls, `new`), and a class's statics after the ones of the same class they read. Two classes referencing each other keep their order, with a warning.
- **`s?.length()` on a null `s` read as 0.** The safe-call chain took the member's own return type (`Int`), so an inferred `var n = s?.length()` became a plain Int, and the null branch wrote an object NULL that reads as 0 — `n == null` was false. A safe call whose tail is a member read or call now has a nullable type (`Int?`, `String?`) and writes a proper primitive null. With `??` folded into the chain the result stays non-null.
- **The right side of `+=` / `-=` / `|=` was cut short at the next `+` or `-`.** It was parsed as the right operand of an arithmetic operator, which stops there for left-associativity, so `a += 1 + 2` added 1 and `result += separator + item` dropped `item`. No error, no warning. The right side is now a whole expression, as with `=`.
- **A compound assignment to an array element did nothing.** `arr[i] += 5` read the element and dropped the update. Primitive elements are now updated in place; object elements (`names[i] += "x"`) already went through `=`.
- **A compound assignment to a nullable primitive (`Int?` local or property) produced invalid C** (`nullable_value += int`). It now null-checks and updates the boxed value.
- **`op -` was compiled under the name of `op /`.** The operator table listed `-` twice and the second entry, `_op__divide`, won, so a class could not declare both, and `/` itself was missing. `op -` is `_op__minus` now. Code that calls an AmLang `op -` by its C symbol, or looks it up by name (am-script's `ScriptOperators`), must use the new name.
- **`%`, `&`, `|`, `^` on `Float` / `Double` are a compile error** instead of C that gcc rejects.
- **An operator function with a different operand type failed validation.** `Vec * Int` (`op * (k: Int)`) was bound correctly but then rejected with "Unidentical types"; the same-type rule now applies to primitive operands only.
- **`const` properties are enforced.** Writing to one outside its initializer, `init { }` and the primary constructor (`=`, `+=`, `-=`, `++`, `--`, …) is now a compile error. The check existed but looked for the property on the wrong expression node, so it never fired, and any code could write to a `const` property.
- **A method call on a nullable-primitive property failed to compile.** `this.age.hash()` with `age: Int?` emitted `if (__is_primitive_null(x) {`: a missing `)` in the null check, present since at least v0.6.0.
- **Object property defaults were not applied (0.14.0 regression).** A class whose only non-zero default was an object — `var name: String = "x"` — was classified as needing no initialisation: object defaults are not baked into the initial property image, so the slot read as zero and neither the image nor `___init_instance` ran. The field stayed NULL and the first use crashed. Such classes run their initialiser again.
- **A subclass constructed into a base-typed variable is initialised as itself.** `var b: Base = new Derived()` chose the initialiser from the expression's type (`Base`), so `Derived`'s property defaults were skipped. The constructed class decides now.
- **`==` binds more loosely than arithmetic.** `a - b == 1` parsed as `a - (b == 1)` whenever a variable or call followed the arithmetic operator — a type error in a value position, and silently wrong code inside `if (… && …)`. The `==` branch of the parser now has the precedence check `!=` already had.
- **The same local name in sibling `try` / `finally` blocks compiles.** The protected body and the `finally` body were rendered without C braces, so `try { var a = … }` twice in one function failed with `redefinition of 'var_a'`. Both bodies are their own C scope now.
- **A field write through a parenthesised cast no longer goes to a same-named local.** `(st as Label).text = text` bound `.text` to the parameter `text` and compiled to `var_text = var_text`, so the field was never written — no error, no warning. Any name chained after a `( … )` group, `as T` or `is T` is now resolved as a member of that value; a name inside the parentheses still resolves to the local. Reads and compound writes (`+=`, `++`) are covered by the same fix.

## [0.14.0] - 2026-10-18

Changes since v0.13.0.

### Added

- **`shared static` properties.** One copy for the whole PROCESS, readable and writable from every thread, instead of the per-isolate copy a plain `static` gets. Each one is emitted as its own C global, and a plain primitive is stored as its own C type — an `Int` is an `int`, not a tagged `nullable_value`. A nullable primitive keeps its tag.

  UNSYNCHRONISED BY DESIGN: no lock, no atomic, no ordering guarantee. A reader on another thread may see a stale value, and a 64-bit type can tear on a 32-bit target such as m68k or PPC32. Guarding it is the caller's job; `Am.Threading.Mutex` is there for that.

  Restricted to primitives, and each restriction is diagnosed rather than ignored: an object or struct is refused, because one process-wide copy would hand a pointer into one isolate's heap to another thread; an initializer is refused, because the global is already zero at load time and a process-wide slot must not be re-initialised by every isolate (assign in `main` before starting threads); and `shared` is refused on an interface, which has no statics at all. `shared` is contextual, so it stays usable as an ordinary identifier.

- **Share-nothing isolate threads.** Static properties live per isolate, addressed through the class's static slot base, and startup emits the static initializer table and boots the main isolate. `Thread.send`/`receive` deep-copy messages between isolates; native classes opt in with `#sendable` (String, Array, Thread) and supply a native copy hook. String constants and annotations are immortal.

- **Fast-lane arenas.** The isolate carries a bump arena used by the allocation scopes below, reclaimed by reference count rather than by scope, so an object that escapes its scope stays correct and only costs retention.

- **Reflection by `#reflect` closure, replacing the `-reflection` flag.** An annotated class gets a read-only descriptor hung on its `aclass`: its properties with name, slot, nullability and declared type, its type arguments, its instance initializer, and a thunk per invokable instance method. `ClassRef` and `PropertyInfo` are built from it lazily, so startup spends nothing, and an unreflected class still answers `getClassRef()` with its name. `-reflection=all` annotates everything.

- **`main` may return `Int`**, and the value becomes the process exit status. A throwing `main` now exits 1 rather than 0, and a throwing `#runOnExit` hook turns a 0 into 1 without overriding a non-zero status `main` set itself.

- **Property-slot initialisation is decided per class, with no flag.** A class whose slots all start as zero bytes gets the allocator's `memset` and nothing else — no `___init_instance` call, since a property that starts as null needs nothing done to it. A class whose starting state is a compile-time constant gets a per-variant `const property` image, memcpy'd by the primary constructor, with the prepared allocator and no init call. A class whose starting state has to be computed keeps `___init_instance` as before.

  This replaces the opt-in `-ftemplate-properties` and the separate inline-defaults path. Measured on am-git: binary 4,087,696 to 4,079,920 bytes (-0.19%, because only 19 variants need an image where the blanket flag emitted 211), and an 18-slot allocation loop 217ms to 207ms. The flag is still accepted so existing build scripts keep working, but it no longer selects anything.

  Still unmeasured on m68k, where a memcpy is a libc call with no wide stores; and there is no slot-count threshold yet, so a two-slot class gets an image where two stores would do.
- **`-fseed-properties` (opt-in, and measured as not worth enabling).** The generated constructors seed every property slot nothing else assigns, so the allocator need only clear the object header. Kept in tree with its measurements so the experiment is not repeated. It also carries a documented invariant hole: three native paths allocate an object without running a constructor, so with the allocator no longer clearing, a property with no initializer is left as heap garbage.

- **`-fescape-report` (prototype, report only).** Census of `new` sites whose object provably cannot outlive its function, as groundwork for promoting them to the arena automatically. Nothing is promoted and the pass runs only under the flag.

- **Allocation scopes.** `scratch { ... }` bump-allocates every object created while the block runs — in callees too, since the switch is a counter on the isolate rather than a lexical region — from the isolate's arena, and reclaims the arena once the objects in it have died. `keep { ... }` is the inverse: it forces the normal heap inside a scratch extent, for objects meant to outlive the block. Both have an allocation-level form, `scratch new T(...)` and `keep new T(...)`, which scopes argument evaluation and the constructor as well as the allocation. The words are contextual, so `scratch`, `keep` and `fast` remain usable as ordinary identifiers.

  An object that outlives a `scratch` block is still correct, but it pins its whole arena until it dies — which is what `keep` exists to avoid. `keep` outside any scratch extent is a no-op, so library code whose allocation is long-lived by design (an interning table, a memo cache, a registry) can use it defensively to stay out of whichever arena its caller happens to have open.

  `fast { ... }` is accepted as the legacy spelling of `scratch { ... }`. The old name described the reward rather than the precondition, which invited applying it to code whose objects survive — the one case it does not help.

- **`#keepAlways` class directive.** Instances of an annotated class never come from a scratch arena, whatever extent is open. It is **inherited**, so the single annotation on `Am.Lang.Exception` covers every exception subclass in core and in user code. `scratch new T(...)` on such a class is rejected rather than silently ignored.

  This is a runtime flag on the class rather than a compile-time rewrite, because the runtime throwers — `__create_exception` and the packed null/bounds/size/OOM site helpers — allocate from C with no `new` site to annotate. Without it, a `throw` out of a `scratch { }` block left the exception in the arena, holding the whole arena for as long as the exception lived.

  Intended for classes whose instances escape by construction or are long-lived by design. It is a per-class, global decision: applying it to something like a map entry would silently disable arena allocation for every such object.

### Changed

- **Arena bookkeeping is O(1) per detach.** The runtime's arena list is doubly linked, so handing an empty arena back no longer scans the isolate's list from the head. This matters once a program holds hundreds of arenas.

- **Borrowed property-slot reads, unconditionally.** A slot read whose window to its last use is call-free skips the retain and release pair, since the property cannot be replaced underneath it. Measured at 30% on the HashSet insert path. This supersedes the `-fborrow-slot-reads` flag, which is no longer read.

### Fixed

- **`amlc docs` lists `shared static` properties**, labelled as such rather than as plain statics, so the per-isolate/process-wide distinction is visible to a reader.

- **`PRIMITIVE_NULL` stamping in the primary constructor.** The stamp loop counted its own ordinal from zero over the class's own property list, so every class with a property-owning base wrote its local ordinals into the base's slots.

- **A name followed by a call binds to the method, not a same-named field.** `map.keys()` bound to `HashMap`'s private `keys` array and then failed to call it, while a differently named method worked.

- **Generics inference, lambda `this` capture, `Any` null operations and chain fixes.** Recursive bounds no longer trip over a class whose base and interface links are still being populated, a `null` literal passed to an `Any` parameter is accepted when the parameter's type carries only a referred class, and `new T().primitiveFn()` no longer declares its box twice.

- **Test binaries of packages that use `shared static` link.** The process-wide globals were defined in the application startup only, so the test startup referenced `<Class>_SS_<name>` symbols that did not exist and the test binary failed to link — while amlc still exited 0.
- **Test startup declares `exit_code`.** The exit-hook failure path is emitted by the test startup too, where the variable did not exist, so any package with a `#runOnExit` hook failed to compile its test binary.

## [0.12.0] - 2026-08-06

### Changed

#### Borrowed parameter convention (performance)

- **Object parameters and `this` are no longer retained by the callee.** Every call site already materialises its arguments as OWNED temporaries that live until the caller's block ends — strictly longer than the call — so the callee-side retain/release bracket was pure overhead: two refcount ops per object argument per call, and under thread-safe ARC two global-lock round trips per call for a cross-thread receiver. Ownership-taking positions stay explicit: returns are `+1` via `__retain_function_return`, property stores retain via propref, and `suspend` functions keep their entry retains (a suspended frame outlives the caller's owned temps). **Native code that stashes an object pointer beyond the call must now retain explicitly** — see the `DO-NOT-STRIP` worker reference in `Thread.c`. Parameters the body assigns to are the documented exception and are bracketed automatically (see below).

### Added

- **`#obsolete` directive** on functions, with an optional message: `#obsolete 'use readAll() instead'`. Every call site produces `Warning: Function '<name>' is obsolete: <message>`. Covers instance, static and extension functions. Warnings are de-duplicated because the binder runs once per function variant.
- **`Am.Lang.BuildInfo`**, a compiler-synthesised class mapping `id -> version` for every non-test package compiled into the binary, backing `Am.Lang.Runtime.getPackages()`. Emitted as ordinary AmLang source through the normal parser pipeline, so it binds, validates and renders like hand-written code. A loaded package counts as test-only when nothing but `testOnly` declarations pull it in; the root package is never test-only.
- **`instances` keyword.** `instances(SomeClass)` reads the live per-class instance count the runtime maintains under `-DTRACKOBJECTS` (which test builds set automatically).
- **Hex literals fold as signed bit patterns**, matching C: `0x80000000` is `-2147483648` as an `Int`, `0x80B` is `-128`, `0xFFFFS` is `-1`. Width-aware and suffix-aware (`B`/`S`/`I`/`L`); a literal too wide for its type is still an error rather than silently truncated.
- **Methods can be called on constants** — `42.toString()` compiles. Identity conversions were deliberately NOT added: `someInt.toInt()` remains an error, and `as Int` stays the preferred (and faster) spelling.
- New scenario tests for all of the above (`ObsoleteDirectiveTest`, `HexLiteralFoldTest`, `ConstantMethodCallTest`, `ParamReassignArcTest`); suite is now **129 tests**.

### Fixed

#### ARC / memory

- **Reassigning a parameter leaked, and could use-after-free.** Assigning to a parameter promotes its slot from a caller-owned borrow to an owning local — the assignment codegen dec-olds and inc-news the slot — so without a matching entry retain and exit release the function both leaked the assigned value and over-released the caller's reference (a latent UAF, not yet observed in the wild). Now collected at bind time in `FunctionVariant.reassignedParams` (including `+=`) and bracketed by `renderFunction` / `renderCodeBlockCleanup`. `suspend` functions are excluded, as they already retain on entry. Locals were never affected.
- **Loop-head temporaries leaked one wrapper per iteration.** Expressions in a `while` condition and similar loop heads re-execute with the temp's cleanup bound to the enclosing block, so the owned handle from the previous iteration was overwritten and lost. Property reads now pre-release before re-assigning (releasing NULL on the first pass is a no-op). This was the chunk-streaming leak.
- **`inline fun` returning from inside a loop leaked every temp** inc'd in the enclosing blocks — for example the array temp of a subscript read inside a `while`. The inline result is now assigned and then unwound through the normal `__returning` / `goto __exit_<block>` cascade, so every enclosing block of the inlined body runs its cleanup decs. The inline body's root block absorbs `__returning`, so the caller's C function does not return; only the inlined block is exited.
- **Exceptions thrown inside an inlined body are re-raised into the caller's block cascade**, taking the same unwind path a `throw` at the call site would, so enclosing `try`/`catch` blocks catch them and every caller block's cleanup decs run.

#### Codegen

- **`var x: T` with no initializer was dropped entirely.** Primitive locals are now zero-seed-declared; seeding before first use is no longer required.
- **`n = null` on a nullable-primitive local (`Int?`) was rejected** — `OperatorExpressionValidator`'s null-to-primitive check ignored the `nullablePrimitive` flag.
- **The wrong `main` could be selected.** When a root application depends on another `type: application` package (e.g. `am-git`), both expose `main` and the last one in iteration order won, silently running the wrong program. The root package's `main` is now preferred.

#### Diagnostics

- **Unresolved method calls name the function, not the receiver.** `0xD2800000.toInt()` reported `Can't inject as operator on expression without evaluating expression '0xD2800000'`; it now reports `Function 'toInt' not found on type 'Am.Lang.Int'`. `ExpressionBinder.triggerExpressionError` walks the sub-expression chain to find the call that failed to resolve.
- Duplicate warnings are suppressed, and `ErrorLogger.getWarnings()` exposes a read-only view for tests.

## [0.11.0] - 2026-07-10

### Added

#### Nullability rework

- **Draft nullability syntax landed.** Bare `T` in a source position is now **nullable by default**; `T!` marks a type non-null. Assignment / return / parameter passing from a nullable to a non-null slot inserts an implicit non-null conversion (`!!assign`, `!!arg`) at bind time; the C codegen null-checks the source and throws `Am.Lang.Exception` on NULL. Field defaults for object types default to `null` when the field is nullable, and to a synthesised `!!` on the initializer otherwise. Primitives keep their old semantics (`Int` non-null; `Int?` nullable-primitive with an explicit `PRIMITIVE_NULL` flag bit).
- **`legacyObjectNullability` compiler flag** in `package.yml.compilerFlags` opts a package back into pre-0.11.0 behaviour: bare object types stay non-null, and every assignment / call that previously compiled continues to compile. Intended for the incremental migration path — set it on the root package and drop it once the source has been audited.
- Per-class `#legacyObjectNullability` directive: same effect as the package-level flag, scoped to one class file. Useful when migrating a large `am-lang-core` file at a time.
- `Type.toNonNullable()` helper for compiler internals; used by `OperatorBinder` and `FunctionCallBinder` to derive the non-null shape at implicit-conversion sites.
- `nullability-draft-test.aml` + `nullability-per-class-directive` fixtures document the accepted shapes.

#### Lifecycle hooks

- Lifecycle hook directives (`#runOnExit`, `#runOnStartup`, and the new `#onNativeTearDown`) now accept an optional integer priority: `#runOnExit(1000)`. Hooks are emitted into `startup.c` in ascending priority order, so a higher number runs later and a negative number runs earlier. Omitting the parentheses keeps priority 0. Ordering is global across all classes (not per-class); equal priorities preserve class-discovery order.
- `#onNativeTearDown` directive: registers a static **native** function to run at process exit, AFTER the GC sweep and per-class shutdown — i.e. once no AmLang objects remain. The compiler collects all `#onNativeTearDown` functions and emits a direct C call to each (straight to the native core symbol, no AmLang forwarding or exception handling, since the runtime is gone), referencing the prototype from the class's generated header which `startup.c` already includes. Intended for native-only teardown such as closing OS libraries opened lazily during the run. The parser rejects it on non-static or non-native functions.

#### Cross-thread ARC (thread-safe reference counting)

- **Wrapper aobject machinery.** When an object is accessed from a thread other than the one that allocated it, the runtime hands the reader a *wrapper* aobject — `class_ptr == NULL`, real object at `object_properties.object_wrapper.wrapped_object`. Reads through the wrapper transparently redirect via `__unwrap()` (an inline macro; identity on `-O0`, real ternary on `-O1+` gated by `__amlc_any_wrappers_alive` so single-thread programs pay ~one load + branch total). Stages 6–9 progressively closed cross-thread hazards: dispatch, property setters, wrapper lifetime, propref-regrowth-UAF and the ARM stale-read race.
- **`__unwrap` inserted at every codegen data-read site.** Native receiver / native args (`String.hash`, `HashMap.get`), `class_ptr` reads for `is`/`as`, array subscripts (`&arr[1]` → `&__unwrap(arr)[1]`), iface-reference reads. Hand-written native functions must call `__unwrap()` themselves — see the new note at the top of `libc/core_inline_functions.h`.
- **Wrapper aobjects respect propref.** `__decrease_reference_count` on a wrapper now gates destruction on `rc == 0 ∧ propref == 0` (not `rc == 0` alone), so a wrapper stored in a cross-thread `List`/`Array` no longer UAFs when the source local scope-exits.
- **Owner-refcount + `owner_gone` protocol.** Wrappers no longer mutate the real's `rc`. The real's owner thread runs a lock-free decrement; wrappers signal end-of-life via a shared `owner_gone` flag. `destruction_claimed` is now a lock-flag distinct from `pending_deallocation` (which stays the same-thread recursion guard).

#### OutOfMemoryException

- **`Am.Lang.OutOfMemoryException`** — subclass of `Am.Lang.Exception`, thrown by `new` codegen when the underlying `calloc` returns NULL. Before this change, allocation failure meant a SIGSEGV in the constructor call.
- **Preallocated singleton at startup.** The runtime allocates one `OutOfMemoryException` at process start (`__init_oom_singleton` in `libc/core.c`, called from `main` and `test_main` right after `clear_allocated_objects`) so the throw path itself never has to allocate. If startup can't allocate the singleton, the process aborts loudly with a stderr message rather than silently crash later.
- **`new` codegen emits a null-check.** After every `__allocate_object` / `__allocate_object_with_extra_size` / `__create_array` call — including the mock and struct-autobox paths — the generated C now reads:
  ```c
  <var> = __allocate_object(&Foo);
  if (<var> == NULL) {
      __throw_out_of_memory_exception(&__result, "at Class.fn on line N (allocation failed)");
      __returning = true; goto __exit_<block>;
  }
  Foo_f_Foo_0(<var>);
  ```
- `Am.Lang.Exception.aml` grows the class + an aggressive comment about the "singleton is re-used across throws so its stack trace grows unbounded — acceptable for a process already in OOM territory" tradeoff.
- **Runtime-helper OOM plumbing.** Follow-up patch to the initial `new`-site guard: `__create_string_constant` / `__create_string` propagate NULL on allocation failure; `__create_exception` falls back to the OOM singleton if it can't allocate a fresh Exception; `__throw_simple_exception` routes to `__throw_out_of_memory_exception` if either of its internal string-constant allocations fails (so bounds checks / negative-array-size throws become catchable OOM instead of SIGSEGV); `__wrap_if_foreign` aborts with a stderr message if `__create_wrapper` returns NULL. Closes most of the "runtime helpers still crash on internal OOM" gap flagged in the initial release notes.
- **`__create_array` size-overflow guard.** `size * item_size` used to wrap `unsigned int * unsigned char` modulo 2^32, so `new Long[Int.max]` silently satisfied a 16 GB request with a ~4 GB buffer; writes past ~512M then smashed unrelated heap allocations. Both operands are now promoted to `size_t` before the multiply, and the total (including the `array_holder` header) is bounds-checked against `(size_t)-1`. Overflow returns NULL, which the codegen's post-`__create_array` guard turns into `OutOfMemoryException`. Also null-checks the allocation result. Closes the last of the three known follow-up items from the initial 0.11.0 release notes.

#### Interface conversions

- **`class C : SubIface` transitively implements `SuperIface`.** `ClassVariant.buildInterfaceImplementations` now recurses through iface-inheritance chains, so the runtime `class_ptr->iface_implementations` list contains every ancestor iface. Drops the old "declare every super-iface explicitly on the class" workaround.
- **Implicit iface-to-iface conversion.** `var s: SuperIface = subIface` compiles when `SubIface` transitively extends `SuperIface`. Explicit `as` still required for unrelated interfaces.
- **Return-position iface upcast.** `bindReturnStatement` now runs the same `injectAsOperator` the assignment / parameter-passing paths use. Without this a `return subIface` from a function typed `: SuperIface` would propagate the sub's iface wrapper unchanged and the caller's slot-0 method dispatch would land on the wrong function.
- **Multi-parent interfaces** (`interface Multi : A, B { }`) with **inherited** functions now resolve at call sites. `allFunctionsWithOverrides` on interfaces walks super-iface chains (with a cycle-guard for diamond inheritance); `findRealClassVariantForFunction` mirrors the walk. Enables shapes like `interface JsHostCallableObject : JsHostObject, JsHostCallable { }` — no need to re-declare `call` on the sub.
- **`is SomeIface` runtime check** — new `implements_interface` runtime helper that walks `cls->iface_implementations` (the pre-fix code called `is_descendant_of`, which only walked `cls->base` and missed every interface). CRenderer picks the right helper based on whether the RHS is a class or an interface.
- **`as SomeIface` codegen** — two fixes: the `.isInterface == true` compile-time gate was widened for downcast-to-iface, and the codegen now unwraps through `iface_reference.implementation_object` when the source is itself an interface (previous shape SIGSEGV'd at the first dispatch through the mis-allocated wrapper).

#### Build targets

- **`buildTargets[].sshBuild`** — SSH+rsync analog of `dockerBuild`. Syncs the build tree to a remote host, runs `make` over ssh, rsyncs `bin/<platform>/` back. Same precedence as `dockerBuild` (a target with both blocks set: docker wins).
  ```yaml
  buildTargets:
    - id: linux-x64-remote
      platform: linux-x64
      sshBuild:
        host: user@buildbox
        remoteBuildPath: /home/user/amlbuilds/myapp
  ```
- **`buildTargets[].dockerTest`** — cross-compile with `dockerBuild`, then execute the test binary inside a container. Landed with the workspace's `amiberry-headless/` image so an `amigaos` test build can be verified end-to-end under Kickstart 3.1 + Amiberry's arm64 JIT without an AmigaOS install on the developer host.
  ```yaml
  buildTargets:
    - id: amigaos-amiberry
      platform: amigaos
      dockerBuild: { image: amiga-gcc:latest, buildPath: /host }
      dockerTest: { image: amlang-amiberry:latest, timeoutSeconds: 900 }
  ```
- **`amlc test` build path routes through `dockerBuild`** (in addition to `amlc build`). Previously the test-mode build was hardcoded to local `make`, so a cross-compile-only target had no way to build the test binary. Same image-allowlist gate as `amlc build`.
- **`=== TEST RUN COMPLETE ===` sentinel** emitted after the test runner's Final Results block. The amiberry-headless container's `entrypoint.sh` polls for this exact string to distinguish "ran to end" from "hung mid-suite" and time out accordingly.

#### Compiler internals & tooling

- **`special` functions** — new mechanism for the compiler to provide a function body directly at codegen time (instead of walking a user-authored AmLang body). Three-file recipe: declare `special fun foo(): T` in the source, whitelist `Class.foo` in `FunctionValidator.knownSpecials`, implement in `CRenderer.renderSpecialFunctionFull`. First user: `Am.Lang.Runtime.getPlatform(): String` returns the compile-time `AM_PLATFORM_ID` string.
- **`Am.Lang.Runtime.getPlatform()`** — static `special` function returning `"linux-x64"` / `"macos-arm"` / `"amigaos"` etc. Backed by the new `-DAM_PLATFORM_ID="<platform.id>"` gcc flag emitted by `MakefileRenderer` for both production and test makefiles.
- **Polyvariant class split** — each type-argument variant of a generic class now lives in its own `.c` file (`List.c` + sibling `List__ta_Am_Lang_String.c`, etc.). `make -j` scales across variants; a single edit to `List.aml` recompiles only the affected variant `.o` files instead of one giant `.c`.
- **Irrelevant-platform C files no longer rendered.** Previously, `CRenderer` emitted native forwarders for every platform in `package.yml` regardless of the active build target. Now only the target platform's files land in `builds/shared/native/`, cutting build-tree size and eliminating spurious "unused file" chatter.
- **Package overrides + local dependencies.** New `path: <relative>` on a dependency entry resolves it from disk instead of the github cache — useful for developing an app + a library side-by-side without pushing every change through the transitive-resolver. Alongside, the `-lpp <root>` CLI flag redirects github-realm transitive dependencies to `<root>/<id>/` (`am-lang-core`, `am-imaging`, ...), so a whole workspace can be built against in-tree edits without vendor-copy juggling.
- **`-rlarc` flag** — arc-site logging. Emits `[arc] site=class.fn:line` comments before every direct `__increase_reference_count` / `__decrease_reference_count` call, plus at ARC injection sites. Off by default; -rlarc turns it on for ARC audits.
- **AmLang `array[i]` bounds check.** Out-of-range subscripts throw `Am.Lang.Exception` with a "IndexOutOfBoundsException: index=N size=M" message. Literal-init subscripts are compile-time proven and exempt.

### Changed

- **`renderRunOnExitCalls` / `renderRunOnStartupCalls`** collect hooks across all classes and emit them in a single priority-sorted pass instead of per-class iteration order. `#runOnExit` placement is unchanged (after `main()` returns, before the GC sweep, so hooks still see live AmLang state).
- **Chained subtraction is left-associative.** `a - b - c` now parses as `(a - b) - c` (was `a - (b - c)`). Same for `/`, `%`, `<<`, `>>`. The `Row.aml` `Short/toShort` workaround is no longer needed. `OperatorBinder` was fixed to match: arithmetic over non-primitive receivers (`String + String + ...`) no longer double-recurses, so left-associative chains bind in O(N) instead of the previous O(2^N) per leaf.
- **Native ARC strip must spare bracket-pairs.** The ARC-strip sweep now only removes `inc`/`dec` pairs that live in the same function. Bracket pairs across function boundaries (e.g. the worker-entry `__decrease_reference_count` matching the caller's `__increase_reference_count`) survive.
- **Test build makefile respects `dockerBuild`.** See "Build targets" above.

### Fixed

- **`try { return X } finally` with `&&`** — codegen now saves and clears `__returning` across the finally block so the return-value expression side-effects don't leak. Fixes the shape where a `finally` short-circuit would drop the `return`.
- **`return` inside `catch` doesn't short-circuit** — code after the try/catch used to still run. The tail is now gated on a success flag.
- **`suspend throw-from-catch` + inline-suspend SEGV** — three-part fix; natural inline shapes work.
- **`suspend` exception lost in resume phase** — `throw` in the resume body was buried in local `__result` and never copied to `__state->result.exception`. Parent saw a default-NULL return and silently coerced throws to NULL returns.
- **`suspend` state-index not zeroed** — child `suspend_state->index` recycled a stale value from the parent frame.
- **`suspend` loop-break gap** — `while` / `loop` with a suspend point inside now iterates correctly (previously broke on the second iteration).
- **`suspend` from non-suspend must return void** — the codegen would emit a value-returning path that the caller couldn't consume; fire-and-forget is now the only supported shape.
- **Nullable-primitive null-compare folded.** `nullablePrimitive` was ignored by the constant-folding guard so `x?.field == null` on a primitive type folded to `false` at compile time.
- **`while (!method())`** no longer NPEs the renderer. Previously a bare `!obj.method()` as a while-condition tripped a codegen path that assumed the negation was on an object reference. Workaround was to hoist to a `Bool` local — no longer needed.
- **Not-operator argument precedence.** `!` bound too loosely against a following argument list. `!x.foo(y)` now parses as `!(x.foo(y))`, matching every mainstream language.
- **`is` / `as` interface unwrap** — reads through `iface_reference.implementation_object` when the source is itself an interface, so `wrapper as Iface` no longer produces a wrapper-of-a-wrapper.
- **Array subscript unwrap.** `&arr[1]` codegen now emits `&__unwrap(arr)[1]`; cross-thread `List<T>.get/set/iter` no longer silently return NULL through wrapper struct overlap.
- **Native primitive-descendant dispatch unwrap.** The receiver is `__unwrap`'d when boxed into `nullable_value` for a native callee (e.g. `String.hash`). Cross-thread `String.hash()` no longer returns 0; `HashMap` lookups no longer falsely miss.
- **Base reference issue** — `super.method()` bound to the wrong class variant when the base was itself a generic type argument's class variant.
- **Don't null-check `this`.** Method bodies used to emit an `if (this == NULL)` guard at every property access on `this`. `this` is always non-null by construction; the check is dead code and now stripped.
- **Number-constant issues** — literal parsing rejected leading `+`, and negative long literals sometimes bound as int-truncated.
- **Struct fixes** — assignment through boxed-struct property references now writes back to the box; nested-struct field access on an rvalue no longer NPEs.
- **String literal `$`** — the string-template pre-scan no longer NPEs when the source contains a bare `$` that isn't followed by an interpolation identifier (dotted/`__` prefixes work as sentinels).
- **Dual operator-renderer resolved.** Two independent branches of the operator codegen were merged into `CRenderer`'s single path, closing a long tail of "works with one flag, breaks with the other" reports.

## [0.10.0] - 2026-04-29

### Added
- Struct value equality now compares fields recursively (including nested structs).
- Additional unit tests for struct comparison and struct-property boxing behavior.
- Class properties now support bare `const propName: Type` syntax in addition to the original `const var propName: Type` form (both are accepted for backward compatibility).
- `inline` keyword for functions: inline functions are expanded at call sites in generated C rather than emitted as regular function calls, enabling zero-overhead abstraction and full GCC constant-folding through the expansion.
- `#implementationPlatforms` directive (placed before a `native class`, alongside `#requireFeature`) declares which platforms need their own per-platform native stub. Example: `#implementationPlatforms "libc", "amigaos", "morphos-ppc"` on `Am.Threading.Thread`. Without the directive, only base platforms get stubs and derived platforms inherit. With it, exactly the listed platforms get stubs — letting one native class share a `libc` implementation across linux/macos while providing custom AmigaOS and MorphOS implementations side-by-side.
- `init { }` block on classes runs as part of object construction, after the primary constructor and after body-declared property defaults. Lets a class derive computed state from its constructor parameters without writing an explicit constructor body — e.g. `class Person(private var firstName: String, private var lastName: String) { private var fullName: String; init { this.fullName = this.firstName + " " + this.lastName } }`. Works with generics (the `init` body can reference type parameters and allocate `new T<...>(...)`) and composes through inheritance: each class's `init` runs in base-to-derived order so derived `init` blocks see fully-set base state. Internally, `init { }` expressions are appended to `_init_instance` and that function is now called *after* the primary constructor, eliminating the previous separate `_init_after_primary_constructor_internal` helper and a subtle ordering bug where the constructor's primitive-flag reset could clobber body-declared defaults.

### Changed
- Struct-typed property boxing is registered more reliably as concrete `Struct<T>` variants.
- Assignment validation for structs tightened to align with non-null struct semantics.

### Fixed
- Struct `==` and `!=` no longer behave like pointer identity checks.
- Writing to boxed struct members (e.g. `obj.structProp.x = value`) now persists correctly.
- Compound assignment operators (`+=`, `-=`, `|=`, `&=`) on fields of a boxed struct property (e.g. `this.position.x += dx`) now correctly write back to the box, so the change is visible to subsequent reads.
- Multiple edge cases in struct boxing/unboxing code generation were stabilized.
- `new ClassName()` expressions now produce a non-null type, so variables inferred from `new` no longer get redundant null-checks before every method call, reducing generated code size.
- Variables annotated with `!` (e.g. `var x: Foo!`) no longer receive a null-check guard before each member access.
- Non-null conversion (`!!`, `!!assign`, `!!arg`) on enum values backed by a primitive type (e.g. `enum Foo<UByte>`) no longer emits an invalid `== NULL` comparison, which previously caused a C compiler warning.
