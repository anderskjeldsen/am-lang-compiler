# AmLang Compiler v0.15.0 Changelog

## [0.15.0] - Unreleased

Changes since v0.14.0.

### Changed

- **Breaking: `for (i = a to b)` now includes `b`; the new `for (i = a until b)` stops before it.** `0 to 3` runs with 0, 1, 2, 3 and `0 to 0` runs once; `0 until 3` runs with 0, 1, 2 — what `to` used to do. Existing loops that index with `to` (`for (i = 0 to arr.length())`) now run one pass too many. Every `to` loop in the AmLang projects has been rewritten to `until`, so their behaviour is unchanged; code elsewhere needs the same rewrite. A `to` loop whose end is a `size`/`length`/`count` read or call warns at compile time, on successful builds too. am-script scripts follow the same rule (`.amsb` cache version 19).

### Added

- **`requiredStack` on a build target.** `requiredStack: 65536` makes the program check its stack first thing at startup and, if it is smaller, print the size needed and exit with status 20 (Amiga family; ignored elsewhere). Needs am-lang-core with `__amlc_require_stack`; an older core builds without the check.
- **Function overloading by parameter type.** Functions may share a name and a parameter count when their parameter types differ, and a call picks the best match by the static types of its arguments: exact class, then nearest subclass, then numeric widening, then `Any` / generic / function-typed / null. Virtual and interface overloads dispatch at run time. Before this, the second declaration was rejected as "already exists", and every call bound to the first function with that name and count. See docs/10-functions.md.
- **`when` statement with smart casts.** `when (x) { is Circle -> … ; 1, 2 -> … ; !is T -> … ; else -> … }` and the subject-less `when { cond -> … }`. In an `is T` branch the subject is typed `T` without an explicit cast — for class, interface and `Any` subjects — including field writes through it. Branches run top to bottom, first match wins; a body is a block or one statement; the subject is evaluated once. `when` is a statement (using it as a value is a compile error) and stays usable as an identifier. See docs/03-keywords.md.
- **`data class`.** `data class Point(var x: Int, var y: Int)` gets generated `equals`, `hash`, `toString` (`Point(x=1, y=2)`) and `copy()` from its primary-constructor properties, so value comparison and hash-based collections work without hand-written `equals` / `hash` pairs. Members the class declares itself are kept; the body is optional; generic data classes work; `data` stays usable as an identifier. See docs/03-keywords.md.
- **`*=`, `/=`, `%=`, `&=`, `^=`** join `+=`, `-=` and `|=`, for locals, properties, statics, array elements, nullable primitives and classes with the matching operator function (`op /`, `op %`, ...).
- **Operator functions `op /`, `op %`, `op &`, `op |`, `op ^`** can be declared (they were rejected as "Operator not found").
- **`if` and `when` as expressions, and expression bodies.** `var s = if (x < 0) "neg" else "pos"` (no braces; `else` required; only the chosen branch runs; a `null` branch makes the type nullable). `when` works in a value position too (`return when (s) { … }`): single-expression branches, an `else`, a plain-variable subject. `fun area(): Int = this.w * this.h` is a function with an expression body. A braceless `if (c) a() else b()` also works as a statement. See docs/03-keywords.md and docs/10-functions.md.
- **Default parameter values and named arguments.** `fun label(text: String, size: Int = 12, bold: Bool = false)` can be called as `label("Hi")`, `label("Hi", bold = true)` or `label(bold = true, text = "Hi")`, and the same works for constructors (`new Pt(y = 7, x = 2)`). Defaults are constants (literals or `null`) and must come after the parameters without one; the caller fills them in. An exact-arity overload wins over one that needs a default. See docs/10-functions.md.
- **`const x: T` in a primary constructor is a read-only property**, like `var x: T` but constant after construction. `const var x: T` (the older spelling) still works.

### Fixed

- **`amlc test` starts coverage tracking before the out-of-memory singleton is created**, since creating it runs instrumented code; a coverage build crashed at startup.
- **`init { }` blocks and property initializers were never validated.** `new MissingClass()` there crashed the renderer with a bare NullPointerException, a type mismatch surfaced as an internal conversion error, and an unknown call (`init { A.nope() }`) built successfully with the call missing from the generated C. They now get the same errors as code in a function, with file and line. Code that was being silently dropped is now a compile error: am-ide, tucan-mail and tucan-paint each have such lines (#61).
- **`amlc test` ignored a platform's `linkerCommand`.** The test executable was linked with the C compiler and its compile options. A platform with a `linkerCommand` (its own or inherited) now links tests the way `amlc build` links the program. Platforms without one are unchanged.
- **`amlc test` compiled with only the target platform's own `gccAdditionalOptions`.** `amlc build` has always added a child platform's options to its parents' and to dependencies', minus `gccRemoveOptions`, plus enabled features' options. The test makefile now collects them the same way, so tests compile with the flags the real build uses.
- **A platform with no `gccCommand` called a command named `null`.** A platform that names no compiler now inherits its C compiler, assembler and linker commands from the platforms it extends, so `amigaos-minigl` can just say `extends: amigaos`. A build target with no compiler at all is reported up front.
- **A failed build left the previous executable in place.** `amlc build`, `run` and `test` now remove the selected targets' executable first, so a failed build can't be mistaken for a working one. Object files are kept, so builds stay incremental.
- **amlc exited 0 when it failed.** A compile error, a failed `make` / docker / ssh build, failing tests, an unknown command and a run whose program failed all ended with exit status 0, so scripts and CI saw success. They now exit 1. A `-bt` naming a build target the package does not define is now an error that lists the defined targets, instead of silently doing nothing, and one whose platform the package does not declare as a non-abstract platform (including a package.yml with no `platforms:` section, which threw a NullPointerException) is an error naming the declared platforms; `amlc test` checks this too (#56, #15, #16). Note that `amlc test` now exits 1 when any test fails.
- **`obj.p = a && b` emitted uncompilable C.** A property or static write whose value was a short-circuit `&&`/`||` read the right operand's temp from outside the block it was declared in (`use of undeclared identifier '__varN'` at `make`), and an array element write (`arr[i] = a || b`) assigned the boxed result to a `bool`. Both now store the expression's result, which is also correct when the left operand decides (#40).
- **Instance members without `this.`.** Calling an instance method without a receiver (`helper()` in an instance method) failed with "Function not found", a bare property as an operator's right operand (`2 * n`, `n = n + 1`, `var area = width * height` in a property initializer) was looked up on the left operand's type, and a bare property read on its own crashed the C renderer. All three now bind as `this.helper()` / `this.n`, as V2 already did; from a static function the error says "Instance function 'helper' can't be called from static function …". A local function value with the method's name wins for `name()`.
- **Static initializers ran before the statics they read.** `static var a: Int = B.b + 1` read 0 (or crashed on a NULL string) when class `A` happened to initialise before `B`, and `static var c = d * 2` above `static var d = 5` read 0. Classes now initialise after the classes their static initializers reference (static reads and calls, `new`), and a class's statics after the ones of the same class they read. Two classes referencing each other keep their order, with a warning.
- **`s?.length()` on a null `s` read as 0.** The safe-call chain took the member's own return type (`Int`), so an inferred `var n = s?.length()` became a plain Int, and the null branch wrote an object NULL that reads as 0 — `n == null` was false. A safe call whose tail is a member read or call now has a nullable type (`Int?`, `String?`) and writes a proper primitive null. With `??` folded into the chain the result stays non-null.
- **The right side of `+=` / `-=` / `|=` was cut short at the next `+` or `-`.** It was parsed as the right operand of an arithmetic operator, which stops there for left-associativity, so `a += 1 + 2` added 1 and `result += separator + item` dropped `item`. No error, no warning. The right side is now a whole expression, as with `=`.
- **A compound assignment to an array element did nothing.** `arr[i] += 5` read the element and dropped the update. Primitive elements are now updated in place; object elements (`names[i] += "x"`) already went through `=`.
- **A compound assignment to a nullable primitive (`Int?` local or property) produced invalid C** (`nullable_value += int`). It now null-checks and updates the boxed value.
- **`op -` was compiled under the name of `op /`.** The operator table listed `-` twice and the second entry, `_op__divide`, won, so a class could not declare both, and `/` itself was missing. `op -` is `_op__minus` now. Code that calls an AmLang `op -` by its C symbol, or looks it up by name (am-script's `ScriptOperators`), must use the new name.
- **`%`, `&`, `|`, `^` on `Float` / `Double` are a compile error** instead of C that gcc rejects.
- **An operator function with a different operand type failed validation.** `Vec * Int` (`op * (k: Int)`) was bound correctly but then rejected with "Unidentical types"; the same-type rule now applies to primitive operands only.
- **`const` properties are enforced.** Writing to one outside its initializer, `init { }` and the primary constructor (`=`, `+=`, `-=`, `++`, `--`, …) is now a compile error. The check existed but looked for the property on the wrong expression node, so it never fired, and any code could write to a `const` property.
- **A method call on a nullable-primitive property failed to compile.** `this.age.hash()` with `age: Int?` emitted `if (__is_primitive_null(x) {`: a missing `)` in the null check, present since at least v0.6.0.
- **Object property defaults were not applied (0.14.0 regression).** A class whose only non-zero default was an object — `var name: String = "x"` — was classified as needing no initialisation: object defaults are not baked into the initial property image, so the slot read as zero and neither the image nor `___init_instance` ran. The field stayed NULL and the first use crashed. Such classes run their initialiser again.
- **A subclass constructed into a base-typed variable is initialised as itself.** `var b: Base = new Derived()` chose the initialiser from the expression's type (`Base`), so `Derived`'s property defaults were skipped. The constructed class decides now.
- **`==` binds more loosely than arithmetic.** `a - b == 1` parsed as `a - (b == 1)` whenever a variable or call followed the arithmetic operator — a type error in a value position, and silently wrong code inside `if (… && …)`. The `==` branch of the parser now has the precedence check `!=` already had.
- **The same local name in sibling `try` / `finally` blocks compiles.** The protected body and the `finally` body were rendered without C braces, so `try { var a = … }` twice in one function failed with `redefinition of 'var_a'`. Both bodies are their own C scope now.
- **A field write through a parenthesised cast no longer goes to a same-named local.** `(st as Label).text = text` bound `.text` to the parameter `text` and compiled to `var_text = var_text`, so the field was never written — no error, no warning. Any name chained after a `( … )` group, `as T` or `is T` is now resolved as a member of that value; a name inside the parentheses still resolves to the local. Reads and compound writes (`+=`, `++`) are covered by the same fix.
